# `is_agc_enabled`, `is_notch_enabled` and `agc_gain_db` are NOT tripwires — they are
# operator-facing state, and they are here because five front-end toggles (SetNotch, SetAgc, SetCessb,
# SetLogbook, SetDcdSquelch) are write-only: a client can set them and can never read them back.
# `agc_gain_db`'s own docstring calls it "a readout of the active-span loop state" where the counters'
# say "tripwire", and the tests that call it assert BEHAVIOUR (gain > 6 dB on a quiet input) while
# using `agc_blocks_processed` as the tripwire in the same test. Two of those toggles make a default
# install display the OPPOSITE of the truth at cold start. These three leave this file when #1276
# wires them into the `MetricsSnapshot` seam — the only one that reads the engine.

# TRIPWIRE(#1271), added 2026-09-04: the counters below exist ONLY so a gate can
# assert that a cross-cutting RX transform actually ran on the PRODUCTION path — the checklist in
# CLAUDE.md ("add a runtime tripwire and assert it increments on the production path") requires
# exactly this, and the asserting test lives in another crate, so the accessor must be `pub`. That
# collides with the project's own rule against exporting API for instruments; the collision is real
# and is recorded here rather than resolved silently. Covered: agc_blocks_processed,
# dc_blocks_processed, dcd_blocks_processed, notch_blocks_processed (all
# crates/openpulse-modem/src/engine.rs). They were grandfathered with NO rationale until #1271.
#
# The collision is narrower than it first looked, and the correction is worth keeping: these are
# `pub` because the asserting tests are INTEGRATION tests in crates/openpulse-modem/tests/, which
# Cargo links as an external crate. That is a PLACEMENT fact, not a principle — and no test asserts
# any tripwire through `server::run` at all, so the "daemon assertion that proves the production
# path" this was justified by does not exist in that form. #1277 carries the structural answer for
# the whole ~65-item class (a Cargo `instruments` feature the compiler enforces), for which
# classifying the 65 is the first deliverable. The cfg-stripper fix that made these visible was
# PR #1272, not issue #1270.
