# Review — #1237: joining `enforced` to whether anything consumes the capability

Reviewer: Fable (adversarial). Date: 2026-08-31. Reviewed **before implementation**, with the
falsifier the issue itself demanded already run. Verdict: *build it — with corrections*. It
falsified part of all four load-bearing claims, including two defects in my own measurement.

## The falsifier, run first

#1237 required, before any code: measure whether a reachability rule would false-fail a capability
that is legitimately library-surface or dormant by design. Result on 162 requirements — **16 are
`enforced`**, all bound; **exactly one** (`REQ-CTL-04`, the motivating case) has every binding in a
package that reaches no binary; **zero** others. So the rule was buildable.

## The trap the issue did not anticipate

`trace.py` accepted two `traceability:` values, and `baseline` is legal ONLY for ids in
`trace-grandfathered-ids.txt`. `REQ-CTL-04` is not there (0 hits, against a control returning 1 for
`REQ-FX-01`). So failing it left **no legal value** — the join could not land without a third
state, and #1237's own text warns that an exemption class is where such a check goes soft.

## What the review overturned

### 1. My measurement was only accidentally correct — two demonstrated defects

The headline numbers reproduced, which is exactly why the instrument needed reading rather than
trusting:

- **Package names are not directory names.** `plugins/bpsk` is package `bpsk-plugin`,
  `plugins/64qam` is `qam64-plugin` — ten packages diverge. Resolving a binding's crate by path
  segment is a **false-FAIL machine for the entire plugin layer**, invisible today only because all
  16 current bindings live under `crates/openpulse-*` where the two coincide. The shipped join
  resolves by `manifest_path`, longest-prefix. Verified: `plugins/64qam/src/lib.rs → qam64-plugin`,
  not dormant.
- **Edge kinds must be filtered.** `cargo metadata` reports dev, build and *optional* edges
  alongside normal ones. **`openpulse-gpu` is depended on ONLY through optional feature-gated
  edges** — my script called it reachable. A GPU requirement bound to a CPU-fallback test would
  then pass both run-evidence and the join while the GPU path never executes in a gated build:
  #1234's keychain shape, one crate over. Filtering to normal non-optional edges moves
  `openpulse-gpu` into the dormant set, where it belongs.

### 2. Crate granularity IS a false-negative machine — and the finer instrument does not replace it

`openpulse-core::pq_handshake` is fully dormant (every entry point in the orphan baseline; its only
outside reference is a `pub use`) inside a crate that reaches every binary, so it passes the join
trivially. But `reachability.py`, the item-level instrument, is **blind to the keystore** — a dead
crate whose two files reference each other looks referenced to it. They are complements; neither
subsumes the other. Shipped as: crate-level join hard-fails, and the docstring names the module-level
gap with `REQ-PQ-05` as its standing example, disposed of explicitly rather than left unsaid.

### 3. Forced promotion would have manufactured the defect it prevents

I proposed that an `unwired` requirement whose package reaches a binary be auto-promoted to
`enforced`. At package granularity, "the package reaches a binary" does **not** imply "this
requirement's capability is wired" — which is the inference #1237 exists to ban. Wiring one keystore
function would have compelled a true-looking `enforced` on every sibling. Changed to an error
demanding **reconciliation**: promote, rebind, or restate.

**This was vindicated within the hour, on unplanted work.** Adding the `psk_key_id` inertness test
to `server.rs` gave `REQ-CTL-04` a binding in a live package; the reverse check fired. Auto-promotion
would have moved the requirement to `enforced` on the strength of a test asserting *the daemon warns
that the knob is inert* — close to the opposite of the statement. The correct reconciliation was to
remove the id from that test.

### 4. Evidence for building it, restated honestly

1 hit in 16 is weak on its own. The case rests elsewhere: the class recurred twice in one day (once
shipped, once as a near-miss in #1234 as filed); the alternative — a hand-maintained registration
checklist — is what this repo has already tried and buried (the signing-domain inventory rotted four
times); and the trap means machinery is required regardless. The standing next victim is
`openpulse-freedv-auth`, the other dormant crate, currently binding-free.

### 5. The inert config knob — found by the review, not by either issue

`ControlSecurityConfig.psk_key_id` is deserialized, defaulted, written into the shipped config
template **and** `docs/config/openpulse.config.toml`, and read by nothing. An operator setting it
got a silent no-op and could believe their PSK came from a keystore. Fixed so the inertness is
audible, with the decision split into a testable function; both describers corrected.

And the framing correction for #1234: for a single PSK on a headless daemon a file keystore is
indirection without security — the master password must itself come from env or prompt. The
keystore's justification is `REQ-CTL-03` (OS keychain, where the OS holds the unlocking secret) plus
multi-secret storage. So the maintainer's question is **"decide REQ-CTL-03's fate"**; wiring or
deletion follows from it, and deletion must also retire the config field and both doc promises.

## Also required and done

Drift on `unwired` routes to FAIL (not warns) — otherwise the new state becomes a way to soften an
existing requirement; `unwired` is refused on capabilities, whose `code:` lists mix wired and unwired
files; the roster prints on every run including passing ones; a missing or failing `cargo metadata`
is a loud FAIL, never a skip; and every describer of the vocabulary was swept (`requirements.yaml`
note, `docs/dev/requirements.md`, the three vocabulary error strings) — the #1120 lesson.
